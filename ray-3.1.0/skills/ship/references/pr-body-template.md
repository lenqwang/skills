# PR Body 模板 + Changelog + 审查就绪看板

## Changelog 格式

从 trace 和 commit 历史提取变更，按类别分组：

```markdown
### {TRACE_ID}: {功能名称}

**Added**
- {用户可感知的新功能，用产品语言}

**Changed**
- {行为变更}

**Fixed**
- {修复的问题}
```

规则：
- 用产品语言（"用户现在可以…"），不用技术语言（"重构了 handleConnect"）
- 每个 commit 至少映射到一个条目
- 内部重构归入 "Internal" 子节（如有）
- **Changelog 条目仅在 Step 6 终端报告中展示，不写入 PR body**

## PR Body 模板

```markdown
## Summary

{一句话摘要：从 trace 场景章节提炼，描述用户可感知的变化}

## References

| 文档 | 链接 |
|------|------|
| 需求 & 验收标准 | [{docs_root}/traces/{2hex}/{TRACE_ID}/trace.md]({docs_root}/traces/{2hex}/{TRACE_ID}/trace.md) |
| 类型合约 | [{docs_root}/specs/{module}/{Component}.spec.md]({docs_root}/specs/{module}/{Component}.spec.md)（如存在；按 module/Component 组织，per-组件长期演进） |
| 审计报告 | [{docs_root}/traces/{2hex}/{TRACE_ID}/audit.md]({docs_root}/traces/{2hex}/{TRACE_ID}/audit.md)（如存在） |

## Test Evidence

- 测试结果：全部通过（{N} tests）
- 审计：`audit_status = {score}/100 | skipped | failed}`（skipped 表示本次未跑 /audit；失败时本应被 ship 拒绝）
- Coder 迭代次数：{N}

---
🤖 Generated by [Ray](https://git.fulltrust.link/fe/ai-plugin-ray) pipeline
```

规则：
- **零内联内容**：Summary 仅一句话，其余全部通过 References 表链接到源文件
- 链接使用 GitHub 相对路径，PR 页面上可直接点击跳转到最新版本
- 如 spec 或 audit 文件不存在，从 References 表中移除对应行；audit 缺失时 Test Evidence 段标注 `audit_status = skipped`
- Changelog 条目不放 PR body，reviewer 可通过 trace 链接和 git log 了解完整变更

## 审查就绪看板

遍历 `{docs_root}/traces/**/audit.md`（per-trace 审计报告，与 trace.md 同目录），聚合该模块的历史审计状态：

```markdown
## 审查就绪看板

### 本次审计
| 维度 | 得分 | 状态 |
|------|------|------|
| 需求一致性 | 23/25 | ✅ |
| 安全性 | 18/20 | ✅ |
| ... | | |
| **总分** | **88/100** | **通过** |

### 模块历史（最近 5 次）
| FEAT-ID | 日期 | 得分 | 结果 |
|---------|------|------|------|
| FEAT-a3f7 | 2026-03-28 | 88 | 通过 |
| BUG-b2c1 | 2026-03-25 | 92 | 通过 |
| FEAT-c4d2 | 2026-03-20 | 72 | 软拒→通过 |

### 未解决技术债
- [ ] {从 tech_debt.csv 中该模块未 resolved 的项}
```

如果聚合到的 `{docs_root}/traces/**/audit.md` 少于 2 个，跳过"模块历史"段。
